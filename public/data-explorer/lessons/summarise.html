Add it up

Lesson 4 of 5 · about 15 minutes

What this lesson is for

This is where the data starts answering real questions: What is the total catch at each district? Which gear brings in the most? How many trips were recorded last month?

All of these are “add it up by group” questions. This lesson shows you how, with two commands. Press Run on each box. Remember: you cannot break anything.

The box below loads the small example table, the same five rows as the last lesson. It runs on its own when the page opens, so you do not have to do anything with it.

If nothing happens at first, R is still waking up — up to a minute the first time, on a slow connection. A small spinning circle on a box means it is working. Wait for it to stop.

Your own landing records are fetched at the same time, under the name landings, so they are ready by the time you need them further down the page.

landings_state = {
  landings_reload;

  yield ({ phase: "loading" });

  const token = localStorage.getItem("authToken");
  if (!token) {
    yield ({ phase: "signed-out" });
    return;
  }

  const apiBase = localStorage.getItem("apiBaseUrl") || "/api";
  try {
    const res = await fetch(`${apiBase}/data-download/explorer-data`, {
      headers: { Authorization: `Bearer ${token}`, Accept: "application/json" }
    });
    if (!res.ok) {
      if (res.status === 401) {
        yield ({ phase: "signed-out" });
        return;
      }
      // 400/403 mean the account cannot reach this data (no forms assigned, district not
      // permitted). Showing "connection problem" there sends the learner hunting a fault that
      // does not exist, so the server's own sentence is passed through instead.
      if (res.status === 400 || res.status === 403) {
        let message = "";
        try { message = (await res.json()).error || ""; } catch { /* body was not JSON */ }
        yield ({ phase: "no-access", message });
        return;
      }
      yield ({ phase: "failed" });
      return;
    }
    // The endpoint returns a bare array. Normalising anyway: `rows.length` is read straight into the
    // panel text, so anything else here would throw and take the whole panel down with it.
    const rows = await res.json();
    const safeRows = Array.isArray(rows) ? rows : [];
    // Absent on an older deployment; the panel then just omits the sentence about the cap.
    const cap = Number(res.headers.get("X-Row-Cap"));
    mutable landings_rows = safeRows;
    yield ({ phase: "ready", rows: safeRows, cap: Number.isFinite(cap) && cap > 0 ? cap : null });
  } catch {
    yield ({ phase: "failed" });
  }
}

A number for each group

A single total for everything is rarely what you want. Usually you want one total per district, or per gear, or per month. That is what group_by() is for: you tell R which column to group on, and then summarise() gives you one answer for each group.

Have a guess first. The example table has 5 rows, in two districts: Shimoni and Vanga.

Your turn: your own district

Now answer the question a supervisor actually asks: “in my district, how much does each gear bring in?”

That means one more step at the front. Filter to your district, group by gear, then add up.

Replace the blanks ______ with one district name from your own data, keeping the quotes, then press Run. Press Hint if you need it.

You can see the district names in your own data with distinct(landings, gaul_2_name). Copy one exactly as it is spelled, between the quotes.

With a district called Kilifi it would be:

landings |>
  filter(gaul_2_name == "Kilifi") |>
  group_by(gear) |>
  summarise(
    total_kg = sum(catch_kg, na.rm = TRUE),
    number   = n()
  )

What you should see: one row per fishing method used in that district, with its total weight and how many catch records there were. That is a real answer to a real question — from your own records.

If the table comes back empty, the district name is spelled differently in your data. Check it with distinct(landings, gaul_2_name) and copy it again.

Now write one from nothing

One last task, and this time there are no blanks to fill. The box below is empty. Write the answer yourself, using the two commands from this lesson.

The question: across all your records, what is the total weight for each kind of fish?

Take your time. Press Hint as often as you need, and Solution if you would rather see it and read it through. Getting there with a hint still counts.

Every answer in this lesson had the same three parts. Start from your table, then group, then add up:

landings |>
  group_by( ... ) |>
  summarise( ... )

The kind of fish is the column catch_taxon, and the weight is catch_kg. Remember na.rm = TRUE so missing weights are skipped.

landings |>
  group_by(catch_taxon) |>
  summarise(total_kg = sum(catch_kg, na.rm = TRUE))

What you should see: one row for each kind of fish in your records, with its total weight. The largest number is the species that brings in the most weight overall.

Want to go further? Add filter(gaul_2_name == "...") as a first step to answer it for your district only.

What you have learned

  • summarise(name = sum(column)) — add a column up into one answer (also mean() for the average, n() for a count).
  • group_by(column) before summarise() — get one answer per group instead of one overall.
  • na.rm = TRUE — skip missing values so you still get a result.

Put together with filter and select from the last lesson, you can now answer most everyday questions about your data: totals and averages, for any group, in any part of your records. That is the whole toolkit — well done.
